# liquid2048

[游戏大厅](https://game.grace-spring.top/) · [liquid2048](https://game.grace-spring.top/2024)

瞄准并发射数字液滴。两滴相同数字的液体接触后合为一滴，数字翻倍。每滴只在首次超过之前达到的数值时为本次合成贡献分数。拆分后合回原数值，即使更换搭档，拆出的部分也不会重复计分。若另一滴首次达到这个数值，它仍会贡献自己的数值。到达 8192 后可以继续合成。液滴可朝任意方向发射，向上发射的液滴受重力落回，期间可继续操作。

## 操作

| 输入 | 选择与发射 | 取消与暂停 |
| --- | --- | --- |
| 鼠标 | 从上沿选择一滴，再从待发区或场内拖动鼠标，松开发射。拖动方向与发射方向相同，拖得越远力度越高。 | 右键或 Esc 取消瞄准。 |
| 触控 | 点选上沿液滴，在液池中拖动并松手。 | 系统中断触控时自动撤销瞄准。 |
| 键盘 | 1–4 选择，方向键瞄准，+ / − 调力度。液池获得焦点后，按住空格预览，松开发射。 | Esc 取消瞄准或暂停。 |
| 标准映射手柄 | LB / RB 切换液滴，左摇杆瞄准，右摇杆上下调力度，按住 A 预览并松开发射。 | B 取消，Start 暂停或继续。 |

液池上沿有四个待发位，圆点标出各个位置。发射后，空位左侧的液滴依次向右平移，新液滴从最左端滑入。向上发射的液滴碰到弹板后反向，接触同值液滴时合成并计分。合成后的液滴留在待发区。打开菜单可暂停、查看记录和更换配色。切到后台时游戏自动暂停。

点按池内的数字液滴可选中它并解除上方的发射锁定。可直接从池内液滴拖动，也可选中后拖动池内空白处，松手向拖动方向短抛。短抛有独立的力度上限，液滴移动期间仍参与普通碰撞和合成。飞溅的小滴先尝试沿着邻滴的边缘回到原液滴，长时间回不去时，可在接触其他池内液滴时被吸收。吸收只转移液量，数值和得分不变。旧的碎滴还在池里时，可继续点按原液滴。快速连点同一滴三下，可将 4 及以上的液滴按数字和液量对半拆分，例如 8 拆成两颗 4，4 拆成两颗 2。2 是最小的数字液滴，各颗拆出的液滴分别参与普通的同值合成与计分。

开局沿用原版 2048 的 90% 出 2、10% 出 4。本局合成出 16 时，补充范围加入 8。之后随最大值逐步开放更大的液滴，最高补充层级比本局最大值低一级，补充值上限为 256。从 2 到 256 的相对权重为 400、64、32、16、8、4、2、1，按本局已解锁的范围归一化。[原版 2048 源码](https://github.com/gabrielecirulli/2048/blob/master/js/game_manager.js)

## 物理与判负

- Rust 每秒推进 120 个固定步，每步做四次接触求解。扫掠排序筛选空间上接近的液滴，分离轴检测计算两个物理轮廓的接触。绘制位置和形变沿用物理状态。
- 液滴用 12 个轮廓点模拟形变。撞击或堆叠时，接触处受压，周围向外鼓起，轮廓在维持面积的同时逐渐恢复。落地后液滴贴住底部并保留厚度。待发液滴的出射速度随拖拽距离非线性增加，范围为 150 到 1370 单位/秒。高蓄力液滴擦过夹缝时更容易横向收窄，减少侧碰对前进速度的影响。两侧的液滴仍受到接触的冲击和形变。正面撞击沿用碰撞求解。重力为 1120 单位/秒²。
- 2 至 4096 的半径依次为 24、30、37、45、54、64、75、86、97、107、116、124。从 8192 起，令 `n` 为超过等级 12 的级数，半径为 `154 − 30 / (1 + 0.16 × n)`。令 `s = 半径 / 24`，质量为 `s²`，柔软度为 `0.64 + 0.36 / s`，速度阻尼为 `0.09 + 0.19 / s`。
- 同值液滴按实体编号稳定配对，在一步内只消费一次。合成结果继承原液滴的质量加权位置与速度，采用新等级的目标半径，后续物理步可再次合成。每滴记录达到过的最高数值，拆出的两滴都继承该记录，合成时取两侧记录与新数值的最大值。新数值高于某一侧记录时，按该侧的数值加分。得分以任意精度整数相加，以十进制字符串从 WASM 传给前端。每个物理合成事件有独立编号，累计成就统计实际产生分数的合成。
- 物理场为 640 × 700，底板位于 y = 676。左右挡板基线分别在 x = 32 与 608，各有 18 单位向外行程。压力来自轮廓接触与持续负载，腾出空间后逐步回弹。
- 四个待发位成组排列，滑动中的液滴按实时位置绘制和响应点选。入口检查考虑液池和其他待发液滴的实际轮廓。两侧压力都达到 98.5%，且所有可用发射位置持续 240 个物理步都堵塞时判负。释放压力或重新出现可用入口会清空危险计时。
- 顶部弹板的恢复系数为 0.58。发射的液滴擦到异值待发液滴时，双方轮廓都会受压，待发液滴向接触方向让位，并在碰撞后逐渐复位。出射液滴保留沿接触面方向的大部分速度。瞄准线会预览碰顶反弹路径。异值液滴可以正常叠放，发射位受堵时会检查附近的净空。设计参考了 Sobosuba 的柔软碰撞演示和开发者公布的待发区净空判定思路。[Sobosuba 官方演示](https://sobosuba.com/) · [开发者对待发区的说明](https://steamcommunity.com/app/1946560/discussions/0/592938395265822959/)
- 池内受到重撞的液滴会在来向形成局部凹陷，两侧鼓起。凹陷在接触解除后逐步收回，经过一次小幅反向回弹后稳定。轮廓变化由实际撞击的方向和力度驱动。

## 成绩、配色与画面

沿用当前浏览器的 `sobosuba.profile.v1` 存档。每局记录起止时间、得分、最大液滴数值、合成次数、发射次数及结束原因。刷新或主动离开会归档本局，最高分随得分保存。音效、减少动态效果和所选配色也在本机保存。

| 成就条件 | 解锁配色 |
| --- | --- |
| 第一次计分合成 | 薄荷汽水 |
| 单局合成 128 | 落日橙糖 |
| 单局合成 1024 | 深海霓虹 |
| 累计完成 100 次计分合成 | 星云果冻 |
| 单局合成 8192 | 晶体汽水 |

默认配色以黄色为主，配色同时覆盖液滴、挡板、池面和界面。每个数值在同一主题内有对应颜色，飞溅的小滴沿用所属数值的颜色。音效由 Web Audio 合成，首次点击开始游戏后启用。减少动态效果时停止装饰性的流动动画，物理形变和碰撞继续运行。

开始页和局内都使用 React Bits Meta Balls 的势场公式。液滴变速时轮廓随惯性拉伸，贴住地面或相邻液滴时沿接触面变形。待发液滴的中心与形变直接取自物理模拟。局内飞溅的小滴有质量和独立的碰撞轮廓，会挤动邻滴，也会被场地和邻滴挡开。飞溅和待发队列使用各自的随机序列。[React Bits Meta Balls](https://www.reactbits.dev/animations/meta-balls)

局内显示场地、待发区、得分和菜单。标题使用 React Bits Tech Text，设置使用 Squish Switch，按钮、弹窗和状态提示复用 daisyUI。大厅采用 [Infinite Menu](https://reactbits.dev/components/infinite-menu) 和 [Reflective Card](https://reactbits.dev/components/reflective-card)。

## 目录与运行

| 路径 | 内容 |
| --- | --- |
| `2024/index.html` | 独立 Vite 页面 |
| `src/sobosuba/` | React 界面、输入、Canvas 渲染、存储和 WASM 接口 |
| `sobosuba-engine/` | Rust 规则、软体模拟及测试 |
| `public/liquid2048-card.png` | 黄色液滴与场地边框的 512 × 512 大厅封面 |
| `tests/sobosuba.spec.ts` | 浏览器玩法与生产路径验证 |

按项目根 README 安装 Bun 1.4.2、Node.js 22.12+、Rust 1.99.0、WASM 目标与 wasm-pack 0.15.1。正式构建从锁定的 Bun 和 Cargo 依赖编译 WASM。Vercel 沿用现有构建配置。访问 `/2024` 会以 308 进入 `/2024/`，查询参数保留。静态资源从站点根部的 `/assets/` 加载。

```sh
bun install --frozen-lockfile
bun run dev
bun run test:rust
bun run lint
bun run build
bun run test:browser
```

运行 `bun run preview` 可手动检查 `dist/`。浏览器测试在未指定外部地址时会自动启动此预览。可用 `PLAYWRIGHT_BASE_URL` 指定已部署的站点。

- Rust 单元测试覆盖同值、异值、多滴竞争、连续合成、待发区碰撞、分级补充、狭缝形变、边界高速撞击、向上回落、8192 以上计分、暂停及双挡板堵塞。
